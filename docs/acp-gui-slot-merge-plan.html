OpenMA ACP 事件与 GUI 槽位合并计划

目标：在不改变 GUI 结构的情况下，尽量覆盖 ACP 官方输入/输出和各 harness adapter metadata，统一经过 ACP / ACP 扩展 → per-harness ACP adapter → OpenMA canonical event → 现有 GUI 槽位。GUI 不解析 harness _meta；无法证明终态时使用 unknown 或 work_item.missing_terminal，不猜完成。

canonical event 已在 main → renderer 传输、SQL persistence 和 SessionStore replay 中作为事实源；旧 raw ACP rows 仅作兼容证据并按 fingerprint 去重。renderer 派生的 native Agent、nested transcript、child usage 与 Monitor delivery 通过 host persistence API 回写 SQL，并已有 Electron 退出后重启 replay 回归。Codex commentary/final_answer 已提升为中立 canonical data.phase，threadStatus/goal 由 Codex adapter 解释，GUI 不读取 _meta.codex。Cursor 2026.07.23 的 create_plan 已同时投影 Markdown 与 todos，update_todos 的 replace/merge 由 canonical update_mode 和 stable entry id 处理；OpenCode 1.18.13 / Kilo 7.4.20 虽不发 ACP Plan，但其精确 todowrite tool 的 typed rawInput.todos 完整快照已由 per-harness adapter 转成 replace-only plan.updated。两条链路都已覆盖 host → SQL → restart replay，GUI 不解析 harness raw metadata。Claude Monitor 是长期事件订阅器：command stdout 行或 WebSocket 文本帧形成异步 delivery。Monitor tool result 的 taskId 是直接身份；WebSocket Monitor 的 SDK task type 为 monitor_ws，可直接分类；command Monitor 与后台 Bash 都先显示为 local_bash，但真实 user-role XML delivery 带稳定 task-id，可将同 ID work item 以 work_item.classified 收敛为 Monitor。快照缺席只产生可逆 missing_terminal，不猜完成。TaskOutput 自 Claude Code 2.1.83 起已 deprecated，仍保持普通 Tool。剩余 gap 是 command Monitor 首次 delivery 前的短暂歧义、没有 direct GUI Stop，以及尚无 Desktop editor owner 的 NES/document。

elicitation/create、可选 elicitation/complete、session/resume、session/list/delete/close/logout 按当前官方文档为稳定能力；plan_update/plan_removed、session/fork、providers、NES/document、MCP-over-ACP 仍是实验或不稳定能力。兼容边界也接受 ACP v2 draft 的 complete user_message、agent_message、agent_thought 和 running/idle state_update，并投影到现有聊天、思考和 session 状态槽位；v2 agent-owned terminal update 暂保留 raw。

明确的剩余 gap

  1. canonical event 已在 main → renderer 传输、SQL persistence 和 SessionStore replay 中作为事实源；旧 raw ACP rows 仅作兼容证据，并按 fingerprint 去重。renderer 派生 native Agent/transcript/usage 通过 host persistence API 回写。
  2. Claude ACP 0.64.2 默认不把 SDK task lifecycle 转成标准 ACP session/update，但可通过 emitRawSDKMessages 以 _claude/sdkMessage opt-in。OpenMA 已下沉可证明的 edge/level 字段；background_tasks_changed 按 REPLACE 处理，缺席只表示 missing_terminal，晚到 task_notification 才能给出 definitive terminal。
  3. Claude Monitor 是长期事件订阅器：命令 stdout 行或 WebSocket 文本帧成为异步 delivery，注入 Claude 并可能触发自主响应。Monitor tool result 的 taskId 是直接身份；WebSocket Monitor 的 monitor_ws 可直接分类；plugin command Monitor 的 local_bash 在首次 delivery 前保持 generic，但 delivery XML 的稳定 task-id 会完成结构化关联。TaskOutput 已 deprecated 且仍是普通查询 Tool。Monitor 尚无 direct GUI Stop。
  4. Pi 0.0.33 是 npm 当前最新；notify 的 warning/error 已投影为 system.notice，info 仍保留 agent message；provider running/queueDepth 已进入 session status 与现有只读 queued placeholder。
  5. OpenCode/Kilo foreground Task 已补齐；todowrite 完整快照已通过 per-harness adapter → canonical Plan → task-list，并通过 SQL/restart replay。background tool return 只证明 running。当前 live ACP emitter 不转发 synthetic user terminal，所以父 turn 结束后显示 missing_terminal；只有 load/replay 中带 audience:[assistant] 的 synthetic user envelope 能恢复 definitive terminal。
  6. available command invocation、permission response 和 steering 已补 canonical 输入事实；adapter 预附事件由 main boundary 补 seq，canonical seq 也已跨 desktop 重启续写。
  7. Stop/tool cancellation、terminal metadata bookend、晚到 update、cancelled PromptResponse 与 Plan update 可见性已有回归；Cursor stable-id todo merge 与 OpenCode/Kilo todowrite replace 已覆盖 host → SQL → Electron restart replay；一次 Stop 不会重复发送 session/cancel。
  8. NES/document 目前只有 Common client API；Desktop 没有 editor owner/facade/IPC，所以不伪造 callback/raw 或 GUI 已适配状态。
